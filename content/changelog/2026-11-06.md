## All accounts can purchase AI Gateway credits

The [AI Gateway](/docs/ai-gateway/overview) lets you add AI features to your app, like summarizing notes, describing uploaded photos, or answering customer questions. One Neon credential gives you more than 60 models from OpenAI, Google, and other providers. You don't need a paid plan to use it anymore. On the Free plan, an organization admin can buy [prepaid credits](/docs/ai-gateway/prepaid-credits) from $5 under **Billing** in the [Neon Console](https://console.neon.tech/app/billing). You pay only for the tokens you use, at each model's rate in the [model catalog](https://neon.com/models). To start building, see [Get started with the AI Gateway](/docs/ai-gateway/get-started).

![AI gateway credits card on the Billing page, showing the credit balance and the Add credits button](/docs/changelog/ai_gateway_free.png)

## Recover deleted projects from the Console

You can now recover a deleted project from the Neon Console, in addition to the CLI and API. Recovery is available for 7 days after deletion. On your **Projects** page, select **Manage** on the banner, then **Recover**. See [Recover a deleted project](/docs/manage/projects#recover-a-deleted-project).

![Recently deleted projects dialog in the Neon Console, listing deleted projects with a Recover button for each](/docs/changelog/recover_projects_console.png)

## Automatic updates for computes up to 16 CU

If you've been manually restarting computes between 8 and 16 CU to keep them current, you can stop. Every compute up to 16 CU, including all autoscaling computes, now gets [compute updates](/docs/manage/updates) automatically. On paid plans, they run in the [update window](/docs/manage/updates#updates-on-paid-plans) you choose.

An update restarts the compute, which typically takes a few seconds. Your data isn't touched, and Neon prewarms the cache during the update, so queries don't run cold afterward. Fixed-size computes above 16 CU still [need a manual restart](/docs/manage/updates#updating-large-computes). To learn more, see [Updates](/docs/manage/updates).

## Give your app its own MCP server

Your customers already use AI agents like Claude, Cursor, and ChatGPT. Now they can use your app from them too. Run an MCP server on [Functions](/docs/compute/functions/overview) and turn on the [OAuth provider plugin](/docs/auth/guides/plugins/oauth-provider) in [Managed Better Auth](/docs/auth/overview). Your users sign in with the account they already have, and the agent can only reach their own data. Start from the template:

```bash
neon functions new mcp-postgres
```

To add sign-in and per-user data, see [Protect an MCP server](/docs/auth/guides/plugins/oauth-provider) with the OAuth provider plugin. For the backstory, read [the blog post](/blog/managed-better-auth-oauth-provider-mcp).

## Set up Junie, Kiro CLI, Pi, and more coding agents with Neon

One command connects your coding agent to Neon, with the Neon MCP Server and agent skills set up for you. Factory Droid, fx, Hermes Agent, Junie, Kilo Code, Kimi Code, Kiro CLI, and Pi are newly supported this week. Run:

```bash
npx neon@latest init
```

To set up one agent, pass `--agent <name>`, like `--agent junie`. Neon works with more than 20 coding agents, including Claude Code, Cursor, Codex, and VS Code. See the [full list of supported agents](/docs/ai/connect-mcp-clients-to-neon#supported-agents-add-mcp).

## New version of the Neon Realtime SDK

Version 0.2.0 of the [Neon Realtime](/docs/realtime/overview) SDK is out. Realtime (beta) turns any SQL query into a live query, so your app's UI updates the moment your data changes. Upgrade for the latest improvements, including sorted live queries that stay sorted as rows change. To upgrade, update the SDK and any adapters you use at the same time:

```bash
npm install @neon/realtime@0.2.0 @neon/realtime-react@0.2.0
```

If you're new to Realtime, start with the [Realtime quickstart](/docs/realtime/quickstart).

## Fixes & improvements

<details>
<summary>**Read replicas**</summary>

- Paid plans now support up to 6 [read replicas](/docs/introduction/read-replicas) per branch. Branches that already have more keep them, but can't add another until they're under the limit. The Free plan limit of 3 per project hasn't changed.

</details>

<details>
<summary>**Neon CLI**</summary>

Update to the latest version to get these changes. See [Upgrade the Neon CLI](/docs/cli/install#upgrade).

- New [`neon postgres`](/docs/cli/postgres) command (aliases `pg` and `lakebase`) groups the Postgres commands and adds `computes`, so you can list, inspect, resize, start, suspend, restart, and delete computes from the CLI.
- [`neon orgs`](/docs/cli/orgs) now manages organizations: `get`, `members` (list, get, update role, remove), `invitations` (list, create), and `spending-limit`.
- `neon roles create --access read_only` or `--access read_write` creates a least-privilege role instead of an admin. Add `--database` and `--schema` to scope it (the schema defaults to `public`). The same `access` option is on `neon.postgres.roles.create` in `@neon/sdk` 7.8.0 and on the MCP Server's `create_postgres_role` tool, so an agent asked for a read-only credential no longer hands out an admin. Without `access`, roles are still created as admins. See [`neon roles create`](/docs/cli/roles).
- New [`neon roles get`](/docs/cli/roles#get) and [`neon roles reset-password`](/docs/cli/roles#reset-password) read a single role and rotate its password.
- New [`neon operations get`](/docs/cli/operations) shows the status, duration, and any error for a single operation.
- [`neon bootstrap`](/docs/cli/bootstrap) now offers to deploy at the end when the template's environment variables are all set. Pass `--deploy` to install, link, and deploy without prompts.
- `neon claim create` and `neon init --claimable` now accept `--project-name`, so a claimable project keeps the name you choose after it's claimed. See [`neon claim`](/docs/cli/claim).
- [`neon init`](/docs/cli/init) now finishes linking your project, writing `neon.ts`, and pulling environment variables even when plugin, skills, or MCP setup fails for one of your agents.
- [`neon plugins`](/docs/cli/plugins) and `neon init` now check that GitHub Copilot CLI and Grok Build actually run before installing the Neon plugin through them.
- `neon init --services data-api` and `neon config init --services data-api` no longer declare Managed Better Auth for a Data API that verifies tokens from an external identity provider such as Clerk or Auth0. They now read how the linked branch's Data API is set up.
- `neon databases delete` and `neon roles delete` now tell you when the database or role is already gone instead of printing nothing, and failed commands no longer print the update notice.
- Commands for Realtime, Functions, function triggers, Object Storage, and the AI Gateway now explain when a feature isn't available in your project's region. The error names the project's region and the regions where the feature runs, instead of a bare 404 (`@neon/sdk` 7.7.0). See [Regions](/docs/introduction/regions).
- A top-level `realtime` key in `neon.ts` now fails with a message that tells you to configure Realtime under `preview: { realtime: true }`.
- [`neon plugins`](/docs/cli/plugins) and `neon init` now always install the Neon plugin user-level. This fixes project-level installs, which failed for every agent in the previous release. VS Code, GitHub Copilot CLI, Grok Build, and Kimi Code no longer need `--global`, and `--global` is still accepted, so existing scripts keep working.

</details>

<details>
<summary>**Managed Better Auth**</summary>

- Managed Better Auth now runs Better Auth 1.7.16, which fixes the issues in Better Auth's [November 3 security release](https://better-auth.com/blog/security-release-2026-11-03). The fix is server-side and already live in every region, so you don't need to do anything: no SDK upgrades, no secrets to rotate.
- A new **Revoke sessions on password reset** setting signs a user out of every existing session after a successful password reset, whether they reset through a link or [Email OTP](/docs/auth/guides/plugins/email-otp#reset-password-with-otp). It's off by default and set per branch. Turn it on in **Settings** > **Better Auth** under **Sign-in with Email**, with `neon neon-auth config email-password update --revoke-sessions-on-password-reset`, or with the [Neon API](/docs/reference/api/auth/update-neon-auth-email-and-password-config). See [Sign users out after a reset](/docs/auth/guides/password-reset#sign-users-out-after-a-reset).
- [`@neon/auth`](/docs/auth/overview) 0.8.1 works with Better Auth UI 1.7. Thrown errors keep the raw error code, password reset and email verification links no longer redirect signed-out users to sign-in, and `auth.middleware()` accepts `publicRoutes` for pages that don't need a session.

</details>

<details>
<summary>**Agent skills**</summary>

- The Neon [agent skills](/docs/ai/agent-skills) now cover branching and egress optimization inside `neon-postgres`, so the standalone `neon-postgres-branches` and `neon-postgres-egress-optimizer` skills are retired. If you installed either by name, install `neon-postgres` instead. The skills also teach Upstash for caching, rate limits, and queues, and the Managed Better Auth OAuth server for MCP and OAuth clients. To install or update the skills, run `npx neon@latest skills`.

</details>

<details>
<summary>**Neon Management SDK**</summary>

- `@neon/sdk` adds a `neon.organizations` namespace for reading an organization and managing its members, invitations, spending limit, and API keys. Every method defaults to the client's `orgId`.
- `neon.auth` now covers the branch-level Managed Better Auth settings, including localhost access, email and password sign-in, the email provider, the magic link, organization, and phone number plugins, and webhooks.

</details>

<details>
<summary>**Neon MCP Server**</summary>

- The hosted [Neon MCP Server](/docs/ai/neon-mcp-server) now supports the [MCP 2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28) (MCP 2.0), and existing clients keep working unchanged. The old HTTP+SSE endpoints, `/sse` and `/message`, are retired and return `410 Gone`. If your client still points at `/sse`, change it to `https://mcp.neon.tech/mcp`. See [Retired HTTP+SSE transport](/docs/ai/neon-mcp-server#retired-sse).
- New tools: `count_projects` answers "how many projects do I have", and `get_project_consumption` and `get_branch_consumption` report usage from the consumption history API.
- Agents can now change Managed Better Auth branch settings, not just read them: localhost access, email and password sign-in, the email provider (with a test send), the organization, magic link, and phone number plugins, and webhooks. `get_neon_auth_config` also reports the new `revoke_sessions_on_password_reset` setting.
- MCP clients and directories now show the server as **Neon**, with its logo, description, and docs link. The server also publishes a Server Card at `https://mcp.neon.tech/.well-known/mcp.json` for discovery before sign-in.
- The `search` and `fetch` tools now work for personal accounts that belong to several organizations. Previously, `search` failed with a "Multiple organizations found" error. Thanks to [breken-ai](https://github.com/breken-ai) for finding and diagnosing the issue.
- Realtime, Functions, trigger, Object Storage, and AI Gateway tools now return the same region-aware error as the CLI when a feature isn't available in your project's region.

</details>

<details>
<summary>**AI Gateway**</summary>

- `@neon/ai-sdk-provider` 1.3.0 uses `gpt-image-2` for image generation by default, since OpenAI deprecated `gpt-image-1`. If you call `neon.tools.imageGeneration()` without a `model`, upgrade or set `model: 'gpt-image-2'` to keep it working. Requests that still name `gpt-image-1` are rejected before they're sent. See [Image generation with Vercel AI SDK](/docs/ai-gateway/openai-responses#image-generation-with-vercel-ai-sdk).
- The [model catalog](https://neon.com/models) now shows each model's lab, plus the context window and sub-cent prices for decision models.

</details>
