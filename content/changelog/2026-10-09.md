## All AI Gateway models now available with prepaid credits

You don't need to request access to frontier models in the [Neon AI Gateway](/docs/ai-gateway/overview) anymore. If you're on a paid plan and have prepaid credits, you can call every model in the catalog, including models from OpenAI, Anthropic, Google, Meta, and Moonshot AI. The [Models](/docs/ai-gateway/models#available-models) page has the full list.

![The AI Gateway page in the Neon Console showing the model catalog](/docs/changelog/ai_gateway_models.png)

To try it, [buy some prepaid credits](/docs/ai-gateway/prepaid-credits#buy-or-top-up-credits), then follow the [AI Gateway quickstart](/docs/ai-gateway/get-started) to make your first request.

## Try Neon's backend features with your coding agent

If you haven't tried [Functions](/docs/compute/functions/overview), [Object Storage](/docs/storage/overview), or the [AI Gateway](/docs/ai-gateway/overview) yet, your coding agent is a good place to start. First, install Neon's [agent skills](/docs/ai/agent-skills) in your project so your agent (Cursor, Claude Code, Codex, or another) knows how these services work:

```bash
npx neon@latest skills -y
```

Then give it something to build. Here are a few ideas:

```text shouldWrap
Add file uploads to my app with Neon Object Storage, and save each file's metadata in Postgres.
```

```text shouldWrap
Create a Neon Function that uses the AI Gateway to summarize support tickets.
```

```text shouldWrap
Schedule a Neon Function to run every night and delete uploads older than 30 days.
```

If you'd rather see the bigger picture first, [How a Neon backend fits together](/docs/get-started/backend-overview) walks through how these services work with Lakebase Postgres and Managed Better Auth.

## Send feedback from the CLI and MCP Server

You can now send us feedback straight from your terminal or your coding agent.

- **Neon MCP Server:** Ask your agent to send it with the new `send_feedback` tool. For example: "send Neon feedback that I'd love a TypeScript example for branching in the docs." See [Neon MCP Server](/docs/ai/neon-mcp-server#available-tools).
- **Neon CLI:** Run `neon feedback --message "<your feedback>"`. You don't need to be logged in. See [neon feedback](/docs/cli/feedback).

Either way, we only get your message. No account, project, or connection details come with it.

You can also use the [Feedback](https://console.neon.tech/app/projects?modal=feedback) form in the Neon Console, or join the conversation in the [feedback channel](https://discord.com/channels/1176467419317940276/1176788564890112042) on our Discord.

## Fixes & improvements

Here are the smaller updates and fixes we shipped this week.

<details>
<summary>**Console**</summary>

- Managed Better Auth plugin settings (Organizations, Magic Link, and Phone Authentication) now live under **Settings** > **Better Auth** with the rest of your auth configuration, instead of on the **Plugins** tab. See [Plugins](/docs/auth/guides/plugins).
- You can now see your project's Object Storage usage in the **Project** panel on the branch **Overview** page. It covers all branches in the project. See [Limits](/docs/storage/overview#limits).
- Fixed an issue in the create-project flow where your region reset to US East (Ohio) when you turned on Object Storage or added a bucket.
- When you delete a project, we now remind you that its custom domains stay reserved, so you can remove any you want to reuse first. See [Delete a custom domain](/docs/compute/functions/custom-domains#delete-a-custom-domain).

</details>

<details>
<summary>**Neon CLI**</summary>

- To sign in, run `neon login`. `neon auth` still works too.
- `neon deploy` and `neon config apply` now accept `-y` (`--yes`), which says yes to every confirmation, including updates to existing settings and changes to protected branches.
- `neon config init --services postgres` creates a Postgres-only `neon.ts`. We removed the `none` option.
- If you're signed out, `neon me` now just tells you so instead of opening a browser to sign you in.
- CLI commands now look for `neon.ts` and `.env.local` in the directory that holds your project's `.neon` file.
- If the CLI fails because of a problem on our side, it now sends us an error report so we can fix it. Reports don't include your arguments, environment variables, or file contents. To turn them off, along with usage analytics, pass `--no-analytics`.

</details>

<details>
<summary>**Managed Better Auth**</summary>

- Fixed an issue where you couldn't create a user without a display name.

</details>

<details>
<summary>**New NAT gateway IPs and Private Networking endpoints in eu-central-1**</summary>

- We added NAT gateway IP addresses and Private Networking VPC endpoint service names in AWS Europe (Frankfurt) (`eu-central-1`). If you allowlist Neon's outbound IPs, add the new addresses from the [Regions](/docs/introduction/regions#nat-gateway-ip-addresses) page so outbound connections don't fail intermittently. If you use Private Networking in this region, add the new service names from the [Private Networking guide](/docs/guides/neon-private-networking).

</details>
