## Managed Better Auth upgraded to Better Auth 1.7

[Managed Better Auth](/docs/auth/overview) now runs Better Auth 1.7.6. Your existing apps keep working with no changes. Sessions, cookies, and JWTs are unaffected, and older SDK versions are still supported.

We've also released new SDK versions built on Better Auth 1.7.6: `@neondatabase/auth` 0.6.0-beta, `@neondatabase/neon-js` 0.8.0-beta, and `@neondatabase/auth-ui` 0.4.0-beta.

If you use a Better Auth client of your own with Managed Better Auth, use Better Auth 1.7 or later.

**Upgrade note:** With the new SDKs, `accountInfo`, `unlinkAccount`, `getAccessToken`, and `refreshToken` identify a linked account by its local account `id`, as returned by `listAccounts()`, instead of the provider's account ID. They no longer accept `providerId`. If you call these methods directly, update your code:

```ts
const { data: accounts } = await authClient.listAccounts();
const google = accounts.find((a) => a.providerId === 'google');
await authClient.accountInfo({ query: { accountId: google.id } });
```

**Known issue:** In `@neondatabase/auth-ui` 0.4.0-beta, the Providers settings card can't unlink an account or show the provider email. A fix is in progress.
