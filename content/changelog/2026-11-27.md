title: Managed Better Auth webhooks on Neon Functions and new signature headers
---

<details>
<summary>**Managed Better Auth**</summary>

- Webhooks can now target a [Neon Function](/docs/compute/functions/overview) on the same branch. A function's invocation URL is the one Neon-hosted URL the webhook URL rules accept. See [Use a Neon Function as the receiver](/docs/auth/guides/webhooks#use-a-neon-function-as-the-receiver).
- Webhook deliveries now carry `Neon-Better-Auth-*` signature headers. The `X-Neon-*` headers are still sent with identical values but are deprecated, and proxies such as Neon Functions strip them. Read one set only. See [Request headers](/docs/auth/guides/webhooks#request-headers).
- The `send.otp` webhook now fires for first-time Email OTP sign-ins, with `user` holding only `email` and `event_data.user_exists` set to `false`. See [`send.otp` event data](/docs/auth/guides/webhooks#sendotp-event-data).
- With sign-up disabled, an Email OTP `sign-in` request for an unknown email returns the same `200` as for an existing account and sends nothing. See [Email OTP limitations](/docs/auth/guides/plugins/email-otp#limitations).

</details>
