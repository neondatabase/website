## Generate embeddings with the Neon AI Gateway

The [Neon AI Gateway](/docs/ai-gateway/overview) now supports embedding models, so you can turn text into vectors through the same OpenAI-compatible endpoint and Neon credential you already use for chat. Call `/v1/embeddings` with either model:

```js
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: process.env.NEON_AI_GATEWAY_TOKEN,
  baseURL: `${process.env.NEON_AI_GATEWAY_BASE_URL}/v1`,
});

const { data } = await client.embeddings.create({
  model: 'qwen3-embedding-0-6b', // or 'gte-large-en'
  input: 'Neon is serverless Postgres',
});
// data[0].embedding is a 1024-dimension vector
```

Both models return 1024-dimension vectors and are billed on input tokens only. New to the AI Gateway? See [Get started](/docs/ai-gateway/get-started) to create a credential and find your branch's base URL. Then store and search the vectors on the same branch as your data with [Lakebase Search](/docs/ai/lakebase-search) or [pgvector](/docs/extensions/pgvector).

<Admonition type="tip" title="What is Lakebase Search?">
Lakebase Search builds on pgvector to give you vector search that scales to over a billion vectors, plus keyword and hybrid search pgvector doesn't offer. It's made up of two Postgres extensions: `lakebase_vector` and `lakebase_text`. To learn more, see [Lakebase Search](/docs/ai/lakebase-search-get-started).
</Admonition>

## Reset a branch's Object Storage from its parent

[Reset from parent](/docs/guides/reset-from-parent) now rolls back a branch's [Object Storage](/docs/storage/overview) along with its Postgres data. When you reset a branch, its buckets and objects return to the parent's current state, so any object storage uploads, overwrites, and deletes you made on the branch are also reverted.

You can reset a branch from the Neon Console, CLI, or API. See [Reset from parent](/docs/guides/reset-from-parent) for the steps.

Resetting Object Storage is available now in AWS US East (Ohio) (`aws-us-east-2`) and AWS Europe (Frankfurt) (`aws-eu-central-1`), with support for additional regions rolling out soon.

## Lakebase Search extensions updated

The Lakebase Search extensions are updated: `lakebase_vector` to 1.1.1 and `lakebase_text` to 0.1.3, with performance improvements and fixes. If you have them installed, upgrade when convenient with `ALTER EXTENSION <name> UPDATE`; see [Upgrade the extension and indexes](/docs/extensions/lakebase-text#upgrade-the-extension-and-indexes).

<Admonition type="note">
Building search with an AI coding assistant? The `neon-postgres` [agent skill](/docs/cli/skills) now includes Lakebase Search guidance for vector, full-text, and hybrid queries. Install it with:

```bash
neon skills -s neon-postgres
```

</Admonition>

## Automating workloads with Neon Functions

Last week we announced that [the Neon backend](/docs/get-started/backend-overview) is generally available, with Functions running next to your database. This week, a [new guide](/guides/neon-function-triggers-cron-and-object-storage) shows how to use Neon Functions to automate workloads with [Function Triggers](/docs/compute/functions/triggers/overview): run a Function on a UTC cron schedule or when a file lands in an [Object Storage](/docs/storage/overview) bucket.

Learn how to declare a function in code using a `neon.ts` file and apply it with `neon deploy`.

```ts
// neon.ts
functions: {
  reports: { name: 'Reports', source: './functions/reports.ts' },
},
triggers: {
  nightly: {
    type: 'schedule',
    function: 'reports',
    cron: '0 6 * * *',
  },
},
```
