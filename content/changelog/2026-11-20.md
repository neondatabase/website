## Postgres 19

Neon now supports **Postgres 19**. We made it available on November 19, the same day the Postgres community released it, with 64 [supported extensions](/docs/extensions/pg-extensions) from day one, so you don't have to wait for the extensions your app depends on. To try it out, [create a new project](/docs/manage/projects#create-a-project) and select **19** as the **Postgres version**.

![SELECT version() returning PostgreSQL 19.0 on a Neon project](/docs/changelog/select_version_19.png)

To test it with your app, spin up a Postgres 19 project next to your current one and copy your data over with the steps in [Upgrading your Postgres version](/docs/postgresql/postgres-upgrade). To see what's new, read our blog post, [Postgres 19 is out: try it on Neon](https://neon.com/blog/postgres-19-is-out-try-it-on-neon), or the official [Postgres 19 release notes](https://www.postgresql.org/docs/19/release-19.html).

## Speed up slow queries with `pg_stash_advice` on Postgres 19

Postgres 19 adds a new extension, [`pg_stash_advice`](/docs/extensions/pg_stash_advice), and Neon supports it on all Postgres 19 projects. When the planner picks a slow plan for an important query, such as scanning with the wrong index, you can fix it without changing your app's SQL. Try advice in your session, keep it if `EXPLAIN ANALYZE` shows the query is faster, then stash it by query ID so Postgres uses it every time that query runs:

```sql
CREATE EXTENSION pg_stash_advice;
SET pg_plan_advice.advice = 'INDEX_SCAN(o orders_customer_id_idx)';
EXPLAIN (ANALYZE, PLAN_ADVICE) SELECT ...;  -- 85 ms became 2 ms in our test
SELECT pg_create_advice_stash('app_stash');
SELECT pg_set_stashed_advice('app_stash', <query_id>, 'INDEX_SCAN(o orders_customer_id_idx)');
ALTER ROLE neondb_owner SET pg_stash_advice.stash_name = 'app_stash';
```

To learn how, see the [`pg_stash_advice` guide](/docs/extensions/pg_stash_advice).

## Official Neon Terraform provider

Neon now has an official Terraform provider, [`neondatabase/neon`](https://registry.terraform.io/providers/neondatabase/neon/latest/docs), in beta. It replaces the previous Neon community provider and manages Postgres along with Functions, Object Storage, Managed Better Auth, Realtime, and the Data API. To install a beta release, pin the exact version:

```terraform filename="main.tf"
terraform {
  required_providers {
    neon = {
      source  = "neondatabase/neon"
      version = "0.19.0-beta.4"
    }
  }
}
```

To get started, see [Manage Neon with Terraform](/docs/reference/terraform). Coming from the previous community provider? The [migration guide](/docs/reference/terraform-migrate) shows how to switch while keeping your Terraform state and databases. Read more in [The Neon Terraform provider is now official](https://neon.com/blog/official-neon-terraform-provider).

## Managed Better Auth adds Discord sign-in

[Managed Better Auth](/docs/auth/overview) now supports Discord as an OAuth provider, alongside Google, GitHub, Vercel, Apple, and Microsoft. Add it from your project's **Better Auth** settings in the Neon Console, the Neon CLI (version 9.5.0 or later), the Neon API, or the Neon MCP Server. Neon has no shared Discord app, so you use your own Discord application's client ID and secret:

```bash shouldWrap
neon neon-auth oauth-provider add --provider-id discord --oauth-client-id <client-id> --oauth-client-secret <client-secret>
```

See [Discord setup](/docs/auth/guides/setup-oauth#discord-setup).

## Track usage across your Neon backend

The [consumption history API](/docs/guides/consumption-metrics) now reports AI Gateway and Object Storage usage for each project, alongside compute, storage, network transfer, and Functions. One request returns usage for all your projects, so you can see how much each project uses. It's available on paid plans, including the [Agent plan](/docs/introduction/agent-plan).

```bash
curl -G "https://console.neon.tech/api/v2/consumption_history/v2/projects" \
  -H "Authorization: Bearer $NEON_API_KEY" \
  -d org_id=$ORG_ID \
  -d from=2026-11-01T00:00:00Z \
  -d to=2026-11-20T00:00:00Z \
  -d granularity=daily \
  -d metrics=compute_unit_seconds \
  -d metrics=root_branch_bytes_month \
  -d metrics=public_network_transfer_bytes \
  -d metrics=functions_invocations \
  -d metrics=ai_gateway_total_tokens \
  -d metrics=object_storage_bytes_month
```

New metrics include:

- AI Gateway: `ai_gateway_input_tokens`, `ai_gateway_output_tokens`, `ai_gateway_total_tokens`, and `ai_gateway_cached_input_tokens`
- Object Storage: `object_storage_bytes_month` and `object_storage_network_transfer_bytes`

See [Consumption metrics](/docs/guides/consumption-metrics) for the full list.

## New OpenAI and Google models on the AI Gateway

The [AI Gateway](/docs/ai-gateway/overview) lets you add AI features to your app, like answering customer questions, summarizing uploaded documents, or generating product images, with one Neon credential for models from many providers. To start building, see [Get started with the AI Gateway](/docs/ai-gateway/get-started). Four new models are available this week:

- **GPT-6.1 Terra** (`gpt-6-1-terra`): OpenAI's newest Terra model, with a 1M-token context window. It costs less per token than GPT-5.6 Terra.
- **Gemini 4 Carbon** (`gemini-4-carbon`): A Google reasoning model with a 1M-token context window that accepts text, images, video, audio, and PDFs. See [Gemini 4 Carbon](/docs/ai-gateway/models/gemini-4-carbon).
- **Gemini 3 Pro Image** (`gemini-3-pro-image`) and **Gemini 3.1 Flash Image** (`gemini-3-1-flash-image`): Generate images from a prompt. Call them on the chat completions endpoint, and the image comes back as an `image_url` content part.

Try the new text models with the AI SDK:

```typescript
import { neon } from '@neon/ai-sdk-provider';
import { generateText } from 'ai';

const { text } = await generateText({
  model: neon('gpt-6-1-terra'), // or 'gemini-4-carbon'
  prompt: 'Explain database branching in one sentence.',
});

console.log(text);
```

See the [model catalog](/docs/ai-gateway/overview#available-models) for capabilities and pricing.

## Add features to your app with new Functions templates

[Neon Functions](/docs/compute/functions/overview) run your backend code, such as APIs, webhooks, and AI agents, on your Neon branch next to your database. This week we added three templates to the [Function Registry](/functions/templates), where they join more than two dozen others you can deploy as a starting point:

- [`workos-sync`](/functions/templates/workos-sync): Copy your WorkOS users, organizations, and memberships into Postgres so you can query them in SQL. A cron job and a WorkOS webhook keep the copy up to date. See [Query your WorkOS users in Neon with the WorkOS Sync Engine](https://neon.com/blog/query-your-workos-users-in-neon-with-the-workos-sync-engine).
- [`notra`](/functions/templates/notra): Track how often ChatGPT, Perplexity, and Gemini mention your brand, with competitor share and content gaps from [Notra](https://www.usenotra.com) (contributed by Notra).
- [`tinysend-email`](/functions/templates/tinysend-email): Send transactional email from a [Tinysend](https://tinysend.com) mailbox, with an idempotency key so a retry sends only once (contributed by Tinysend).

List the templates and start a function from one with the [Neon CLI](/docs/cli):

```bash
neon functions templates list
neon functions new tinysend-email
```

Have a template to share? Open a pull request on [neondatabase/examples](https://github.com/neondatabase/examples/blob/main/registry/CONTRIBUTING.md). The contributing guide covers the template format, how to test it locally, and what we check in review.

## Neon is available as a Kiro Power

You can now install Neon as a [Kiro](https://kiro.dev) Power. One install adds the Neon agent skills and the Neon MCP Server, in both the Kiro IDE and Kiro CLI. In the Kiro IDE, use the [one-click install link](https://kiro.dev/launch/powers/add?name=neon). In Kiro CLI, run:

```bash
/powers install neon
```

After you install, run `/mcp` to authenticate the Neon MCP Server. See [Kiro](/docs/ai/connect-mcp-clients-to-neon#kiro).

## Fixes & improvements

<details>
<summary>**Agent skills and plugins**</summary>

- `npx neon@latest plugins --agent codex` and `--agent kimi-code` now set up the Neon MCP Server along with the skills. Before, the skills installed but Codex and Kimi Code had no Neon MCP Server configured. If you installed the plugin in either agent earlier, run the command again. See [Set up Neon in Codex](/docs/ai/agent-setup/codex).
- The [agent skills](/docs/ai/agent-skills) now cover Discord sign-in for Managed Better Auth, point agents at [Add Realtime to an existing app](/docs/realtime/quickstart#add-realtime-to-an-existing-app), and link the per-module Realtime SDK reference pages. To update, run `npx neon@latest skills`.

</details>

<details>
<summary>**Neon MCP Server**</summary>

- Fixed `restore_snapshot` overwriting the snapshot's source branch when called without a target branch. For a snapshot of your default branch, that's production. Restores now stay un-finalized by default, as they do in the [Neon CLI](/docs/cli/snapshots#restore), so you can check the restored branch before you swap it in.
- Tool results now include the credentials Neon issues, such as connection strings, role passwords, and the Managed Better Auth server key, so your agent can finish setups that need them. Choose what's shown with `?secrets=setup` (the default), `all`, or `none` on the server URL. See [Secrets in tool results](/docs/ai/neon-mcp-server#secrets-in-tool-results).
- Every tool now has an output schema and returns `structuredContent`, so clients can read and check tool results.
- `describe_table_schema` now lists every constraint, including for roles that only have `SELECT` and for `EXCLUDE` constraints, and finds mixed-case table names such as Prisma's `User`.
- `enable_realtime` is now marked as destructive, so your client asks before running it. Enabling [Realtime](/docs/realtime/overview) permanently turns on logical replication for the project and suspends its computes, which drops active connections.
- Tool errors caused by a Neon API 5xx now include the HTTP status and request ID, which helps when you report the problem.
- Opening `https://mcp.neon.tech/mcp` in a browser now shows a setup page, and `https://mcp.neon.tech/mcp.md` serves the same guide in Markdown for agents.
- Fixed Codex losing its connection to the hosted MCP Server after a restart.

See [Neon MCP Server](/docs/ai/neon-mcp-server).

</details>

<details>
<summary>**Neon CLI**</summary>

- If you belong to more than one organization, project commands no longer pick a project for you when you omit `--project-id`. Before, the CLI could choose a project from your default organization, so a command such as `neon roles create` could change a project you didn't intend. Pass `--project-id` or `--org-id`, or [link](/docs/cli/link) the directory to a project.
- [`neon me`](/docs/cli/me) now works with organization API keys and shows the organization.
- Browser sign-in now waits up to 10 minutes instead of 60 seconds. When there's no terminal, as when a coding agent runs a command, the CLI now fails right away instead of waiting for a browser sign-in.
- `neon realtime enable` and `neon status` now report whether [Realtime](/docs/realtime/overview) is live on the branch.
- `neon skills --skill <name>` installs into the agent you're using without `-y` or a terminal.
- `neon docs <query>` is now a shorthand for [`neon docs search`](/docs/cli/docs).
- When `neon init` links an existing project, it now writes a `neon.ts` that matches the services already set up on the branch, such as Managed Better Auth, the Data API, Object Storage, or Realtime, so `neon env pull` brings in their variables.
- `neon init` now installs dependencies with a package manager that's on your `PATH` when a project has lockfiles from more than one, as apps exported from app builders often do.
- `neon credentials reveal --output json` now includes the credential's `branch_id`, like `create` and `rotate`.
- Fixed `neon init` asking for a next step when `neon.ts` sets up only the AI Gateway, `neon functions new` generating a router that fails Next.js linting, and `neon claim delete` leaving an empty `.neon` file behind.

To upgrade, run `npm install -g neon@latest`.

</details>
